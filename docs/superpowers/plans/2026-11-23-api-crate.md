# eywa-api Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Eywa's v1 wire types as an `eywa-api` crate and make the server, and `eywa top`, use them.

**Architecture:** The repository becomes a Cargo workspace with a new `eywa-api/` member that depends only on serde and serde_json. The server uses the crate's enums directly, builds the crate's `Row`, and serializes the crate's `Message`. `eywa top` decodes the same types.

**Tech Stack:** Rust 2024 (1.88), serde, serde_json.

**Spec:** `docs/superpowers/specs/2026-11-23-api-crate-design.md`

## Global Constraints

- `eywa-api`: edition 2024, `rust-version = "1.88"`, `publish = false`, MIT. Its only dependencies are `serde` (with `derive`) and `serde_json`.
- The wire format doesn't change, apart from key order inside objects. Every error code and message from request parsing stays exactly as it is.
- Every crate enum has `#[serde(other)] Other`, and `Message` has an `Other` for unknown types. The server never produces `Other`.
- After every task, `cargo fmt --check`, `cargo test --workspace` and `cargo clippy --workspace --all-targets -- -D warnings` pass.

## Review Focus

1. **A newer Eywa sends a message type, field, attribute or enum value this version doesn't know.** Decoding succeeds, and unknown attributes are kept. Test: `decodes_what_a_newer_eywa_may_send` (Task 1).
2. **An attribute arrives with an unexpected JSON type,** such as a string `pid`, when the server turns a node's map into `Attrs`. The row is still published, with that key kept in `other`. Test: `attrs_with_unexpected_types_keep_the_row` (Task 3).
3. **Every message the server writes decodes back to an equal value.** Test: `every_published_line_round_trips` (Task 3).
4. **Request errors stay byte for byte.** Covered by the existing `tests/service.rs` error tests, which must pass unchanged (Task 2).
5. **`eywa top` on a stream with unknown types and fields** keeps rendering. Test: `top_ignores_unknown_messages` (Task 4).

### Task 1: The `eywa-api` crate

**Files:**
- Modify: `Cargo.toml`. Add `[workspace] members = ["eywa-api"]` and the dependency `eywa-api = { path = "eywa-api" }`.
- Create: `eywa-api/Cargo.toml` and `eywa-api/src/lib.rs`.

**Produces:** in `eywa_api`, all deriving `Serialize`, `Deserialize`, `Clone` and `Debug`, and `PartialEq` where possible:
- **Enums.** `Kind`, `State`, `Reason`, `Outcome`, `Origin`, `Approvals`, `Interrupts`. Each is snake_case on the wire, except `Outcome`, which is lowercase. Each has an `Other` variant marked `#[serde(other)]`, and each also derives `Copy`, `Eq` and `Hash`.
- **Requests.** `Op` (`Get`, `Subscribe`, `Stop`) and `View` (`Tree`, `Requests`), and `Request { v: u32, op: Op, view: Option<View>, path: Option<String>, depth: Option<u32> }`. The `None` fields are skipped. Constructors: `Request::subscribe(path: &str, depth: u32)` and `Request::requests()`, both with `v: 1`.
- **Rows.**
  - `Counts { sessions, needs_input, working, unknown, idle: u32 }`
  - `LastTurn { outcome: Outcome, ended_at: String }`
  - `Observes { agents: bool, approvals: Approvals, questions: bool, mcp_input: bool, interrupts: Interrupts }`, which also derives `Copy`.
  - `Attrs`: every documented attribute as an `Option`, with the `None` fields skipped, plus `#[serde(flatten)] pub other: serde_json::Map<String, Value>`. It also derives `Default`.
  - `Row { id: String, kind: Kind, state: State, since: String, reason: Option<Reason>, cause: Option<String>, counts: Option<Counts>, attrs: Attrs }`, with the `None` fields skipped.
- **Messages.** `Message` has the variants `Snapshot { rev: u64, rows: Vec<Row> }`, `Upsert { rev: u64, row: Row }`, `Remove { rev: u64, id: String }`, `Error { code: String, message: String }`, `Stopping` and `Other`. It serializes with `"v":1` and `"type":<snake_case>`, and decodes ignoring `v`.
- **Location.** `pub const API_SOCKET: &str = "api.sock";` and `pub fn default_dir() -> PathBuf`, which returns `$EYWA_DIR`, else `$HOME/Library/Application Support/eywa`. Move the body from `src/hook.rs`.

- [ ] **Step 1: Write the failing tests** in `eywa-api/src/lib.rs` `mod tests`:
  - `serializes_messages_with_v_and_type`. `Message::Remove { rev: 3, id: "/claude".into() }` serializes to JSON equal to `{"v":1,"type":"remove","rev":3,"id":"/claude"}`. `Message::Stopping` serializes to JSON equal to `{"v":1,"type":"stopping"}`.
  - `decodes_a_documented_row`. Decode the request row from the README, with `attrs` `{ "reason": "approval", "prompted": true, "tool_name": "Bash" }`. Assert `kind == Kind::Request`, `state == State::NeedsInput`, `reason == Some(Reason::Approval)`, `attrs.tool_name.as_deref() == Some("Bash")` and `attrs.prompted == Some(true)`. Then re-serialize and compare as `Value` to the input.
  - `decodes_what_a_newer_eywa_may_send`:
    - `{"v":1,"type":"heartbeat"}` gives `Message::Other`.
    - A row with `"kind":"robot"`, `"state":"sleeping"` and `"reason":"vibes"` decodes `Other` for all three.
    - An extra top-level field `"glow":1` is ignored.
    - In `attrs`, `{"colour":"red","observes":{…,"approvals":"someone","interrupts":"psychic"}}` keeps `other["colour"] == "red"` and decodes `Approvals::Other` and `Interrupts::Other`.
  - `subscribe_request_matches_the_docs`. `Request::subscribe("/", 1)` serializes to JSON equal to `{"v":1,"op":"subscribe","path":"/","depth":1}`.
- [ ] **Step 2: Run** `cargo test -p eywa-api`. Expected: compile errors for the missing types.
- [ ] **Step 3: Implement the crate.**
- [ ] **Step 4: Run the Global Constraints commands.** Expected: everything passes, with the existing `eywa` tests unchanged.

**Files:**
- Modify: `src/tree.rs`, `src/adapter/{mod,claude,codex,grok,muse}.rs`, `src/api.rs`, `src/hook.rs`, `tests/common/mod.rs`, and any other file that names these types.

**Consumes:** Task 1's enums, `Observes` and `default_dir`.

- [ ] **Step 1: Swap the definitions.**
  - Delete `tree.rs`'s `Kind`, `State`, `Outcome`, `Observes`, `Attribution` and `Detection`, and `pub use eywa_api::{Kind, State, Outcome, Observes, Approvals, Interrupts};` in their place.
  - `Kind`'s inherent methods (`from_prefix`, `allows_child`, `is_work`) become free functions in `tree.rs`.
  - `Attribution` becomes `Approvals` and `Detection` becomes `Interrupts` everywhere, including the `CLAUDE` fixture.
  - `adapter::Reason` becomes `eywa_api::Reason`, with its `label` kept as a private function.
  - `api::Op` becomes `eywa_api::Op`.
  - `hook::default_dir` calls `eywa_api::default_dir`.
  - A match on these enums handles `Other` with `unreachable!("the server never produces Other")`, or folds it in where that reads better. For example, `State::Other` counts as idle in `counts`.

### Task 3: The server publishes the crate's `Row` and `Message`

- Test: `tests/service.rs` and a unit test in `src/row.rs`.

**Consumes:** Task 1's `Row`, `Counts`, `Attrs` and `Message`.

- [ ] **Step 1: Write the failing tests.**

  - `attrs_with_unexpected_types_keep_the_row` in `src/row.rs`: a node whose map has `"pid": "not a number"` and `"cwd": "/tmp"` publishes a row with `attrs.cwd == Some("/tmp")` and `attrs.other["pid"] == "not a number"`.

  - `snapshot_line`, `change_line`, `stopping_line` and `error_line` serialize `Message` values.
  - `row::Change` keeps holding the crate's `Row`.
- [ ] **Step 4: Run the Global Constraints commands.** Expected: everything passes. If an existing test compares raw JSON strings and only the key order differs, change it to compare `Value`s, and say so in the commit message.
